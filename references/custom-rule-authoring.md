# 专属标书生成规则制作模式

本模式属于 `biaoshu-master` 的规则管理分支，不启动 G0 至 G7 标书制作流程，也不创建项目工作区、阶段推荐或交付文件。

## 触发条件

只有当前用户消息同时满足以下两点，才进入本模式：

1. 明确引用 `biaoshu-master` 技能（包括 `$biaoshu-master` 或“请用biaoshu-master技能”）；
2. 包含“制作专属的标书生成规则”这一意图或等价明确表达。

用户从 Stage4 点击“新建专属规则”后复制的标准引导语是：

> 请用biaoshu-master技能，帮我制作专属的标书生成规则

只出现“新建规则”“换个规则”但没有明确引用本技能时，不要自动启动本模式；先请用户发送标准引导语。

## 对话引导顺序

一次只推进一个问题，先收集最影响规则结构的信息：

1. 适用领域和项目类型：例如电信运维、系统集成、政府咨询、物业服务或科研项目；
2. 希望强化的评分与写作重点：例如 SLA、接口、调研、培训、验收、保密或成果转化；
3. 必须遵守的专属要求和明确禁用内容；
4. 可供参考的本机文件绝对路径。先判断文件是项目事实、历史案例还是可提炼的规则，不能把参考项目的客户、人员、业绩、数字、日期和承诺写进规则；
5. 用户希望的规则名称、简介，以及是否在后续项目中设为默认。

收到资料后，先输出规则草案和“默认规则仍然保留、该文件只作为领域覆盖层”的说明，等待用户明确确认。用户未确认前不得写入 Skill。草案必须是可执行的 Markdown，至少包含适用范围、强化写作要求、事实边界、结构/评分要求、重复控制、格式或交付特殊要求和领域禁忌。

## 本地写入

用户确认草案后，将草案保存为临时 Markdown，再使用以下命令登记到 canonical Skill：

```bash
python3 scripts/rule_profiles.py register \
  --source <临时规则Markdown绝对路径> \
  --name "<规则名称>" \
  --description "<一句话说明>" \
  [--id <小写规则ID>]
```

登记脚本只写入`rules/custom/<id>.md`并更新`rules/rule-index.json`，不会覆盖`references/stage4-writing-rules.md`、预设规则或用户项目资料。登记后必须运行：

```bash
python3 scripts/rule_profiles.py list
```

核对新规则的ID、名称、摘要和文件摘要；用户要求设为默认时，再运行`python3 scripts/rule_profiles.py set-default <id>`并重新列出确认。默认设置只影响之后打开的Stage4选择页，不改写已经授权的项目，也不改变历史交付快照。

## 结束条件

规则登记与校验完成后，告知用户规则名称、规则ID、保存位置和是否已设为默认；不要开始任何标书生成阶段。下一次正式制作时，Stage4 选择页会显示默认规则、三个预设和用户自定义规则；选中的规则会与本次授权、项目规则快照和后续 AI 复校绑定。
